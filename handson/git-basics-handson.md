> 対象：ノンエンジニア向け / 所要時間：30〜45分

## Git を「ゲームのセーブ機能」で理解する

Git は **ファイルの変更履歴を管理するツール** です。
ゲームに例えると、こんなイメージです。

| ゲーム | Git |
|--------|-----|
| セーブデータ | リポジトリ（履歴の保管場所） |
| セーブポイント | コミット（その時点のスナップショット） |
| 「冒険日誌に記録する」前のメモ書き | ステージング（addした状態） |
| 別データでやり直す | ブランチ（並行して別の作業をする） |

---

## 今日のコマンド一覧

```
git add        → 変更を「次のセーブ候補」に入れる
git commit     → セーブポイントとして記録する
git branch     → 今あるブランチの一覧を見る
git checkout -b → 新しいブランチを作って移動する
git checkout   → 別のブランチに移動する
```

---

## Part 1 : `git add` — 付箋を貼る

### たとえ話

お客様に提出するレポートを書いているとします。
机の上にいくつか変更したページが散らばっています。

`git add` は「このページを次の提出物に含める」と **付箋を貼る** 作業です。
付箋を貼っただけで、まだ封筒には入っていません。

### 基本の使い方

```bash
# 特定のファイルだけ候補に入れる
git add ファイル名

# 例
git add README.md

# 変更したファイルをすべて候補に入れる
git add .
```

### 状態を確認する

```bash
git status
```

実行すると…

```
Changes to be committed:    ← addした（付箋あり）
  modified: README.md

Changes not staged:         ← まだaddしていない（付箋なし）
  modified: notes.txt
```

### ポイント

- `git add` しただけでは **履歴には残らない**
- 「後で追加しようと思っていたけどやっぱりやめた」もOK（addを取り消せる）
- チームで作業するとき、関係ないファイルを混ぜないためにある

---

## Part 2 : `git commit` — セーブポイントを作る

### たとえ話

付箋を貼ったページを封筒に入れて、**日付とメモを書いて保存する** イメージです。

ゲームで言えば「ここでセーブ」のボタンを押す瞬間。
何かあったらこの時点に戻ってこれます。

### 基本の使い方

```bash
git commit -m "メッセージ"
```

`-m` の後の文字列が **セーブポイントにつける名前**（メモ）です。

```bash
# 例
git commit -m "ログイン画面のボタンの色を変更"
git commit -m "テストケースを3件追加"
```

### よくあるミス：メッセージが雑だと後で困る

```bash
# ❌ 後で見てもわからない
git commit -m "修正"
git commit -m "update"

# ✅ 何をしたかわかる
git commit -m "トップページのタイトルを日本語に変更"
git commit -m "ボタンクリック時のエラーハンドリングを追加"
```

### コミットの履歴を見る

```bash
git log --oneline
```

```
a3f9c12 トップページのタイトルを日本語に変更
7e1b304 ヘッダーのロゴを更新
2c8d001 初期ファイルを作成
```

セーブポイントの一覧が新しい順に並びます。

## Part 3 : `git branch` と `git checkout -b` — 別ドラフトで作業する

### たとえ話

会社のWebサイトを複数人で改修しているとします。

- Aさん：「お問い合わせページ」を改修中
- Bさん：「採用ページ」を追加中
- Cさん：緊急バグを修正中

全員が同じファイルをそのまま触ると、お互いの変更が混ざって大変なことになります。

**ブランチ** は、本体のファイルを **コピーして別のスペースで作業できる** 仕組みです。
完成したら本体にマージ（合体）します。

```
main ブランチ（本番・正式版）
  │
  ├── feature/contact-page   ← Aさんの作業スペース
  ├── feature/careers-page   ← Bさんの作業スペース
  └── hotfix/login-bug       ← Cさんの緊急修正
```

### 今いるブランチを確認する

```bash
git branch
```

```
* main          ← *がついているのが今いるブランチ
  feature/test
```

### 新しいブランチを作って移動する

```bash
git checkout -b ブランチ名
```

`-b` は「**b**ranch（ブランチ）を新しく作る」のオプションです。

```bash
# 例：お問い合わせページ用のブランチを作る
git checkout -b feature/contact-page
```

実行後は自動でそのブランチに移動します。

```
Switched to a new branch 'feature/contact-page'
```

### ブランチ名のよくある命名ルール

```
feature/機能名    → 新機能を追加するとき
fix/バグ名        → バグを修正するとき
hotfix/緊急修正名 → 緊急で本番に当てる修正
test/テスト名     → テストを追加するとき
```

## Part 4 : `git checkout` — ブランチを切り替える

### たとえ話

複数の「作業部屋」があって、その部屋を **移動する** コマンドです。

### 既存のブランチに移動する

```bash
git checkout ブランチ名
```

```bash
# 例：mainブランチに戻る
git checkout main

# 例：別の人が作ったブランチに移動する
git checkout feature/careers-page
```

### ⚠️ 切り替え前に注意！

ブランチを切り替える前に、作業中の変更は **必ずコミットかスタッシュ**（一時退避）しましょう。
コミットしないまま切り替えると変更が別のブランチに混入することがあります。

```bash
# ブランチを切り替える前の安全な手順
git add .
git commit -m "作業途中：○○を修正中"
git checkout main
```

## 全体の流れ（まとめ）

```
1. 作業用ブランチを作る
   git checkout -b feature/my-work

2. ファイルを編集する（エディタで普通に編集）

3. 変更を候補に入れる（付箋を貼る）
   git add .

4. セーブポイントとして記録する
   git commit -m "○○を修正した"

5. 必要に応じて 3〜4 を繰り返す

6. 完成したらmainブランチに戻る
   git checkout main
```

## ハンズオン練習

### 準備

```bash
# 練習用フォルダで試す場合
cd ~/Desktop
mkdir git-practice
cd git-practice
git init
```

### 手順

```bash
# 1. mainブランチにファイルを作る
echo "本番用メモ" > memo.txt
git add memo.txt
git commit -m "最初のファイルを作成"

# 2. 作業用ブランチを作る
git checkout -b feature/edit-memo

# 3. ファイルを編集する
echo "新しい内容を追加" >> memo.txt

# 4. 変更を保存する
git add memo.txt
git commit -m "メモに新しい内容を追加"

# 5. 履歴を確認する
git log --oneline

# 6. mainに戻って比較する
git checkout main
cat memo.txt   # mainブランチのmemo.txtは変わっていないはず

# 7. ブランチを確認する
git branch
```

## よくある質問

**Q. `git add .` と `git add ファイル名` はどう使い分けますか？**
> 関係ないファイルも誤って含めてしまうリスクがあるため、本来は `git add ファイル名` が丁寧です。自分だけが触っているフォルダでは `git add .` でも問題ありません。

**Q. コミットメッセージは日本語でいいですか？**
> チームのルールに合わせましょう。日本語で書くチームも多いです。大事なのは「何を変えたか」が後でわかることです。

**Q. ブランチを作りすぎても大丈夫？**
> 大丈夫です。マージ済みのブランチは後で削除できます（`git branch -d ブランチ名`）。作業ごとにブランチを分ける習慣はむしろ推奨されます。

**Q. `git checkout -b` と `git branch` の違いは？**
> `git branch ブランチ名` はブランチを作るだけで、今いる場所は変わりません。`git checkout -b ブランチ名` はブランチを作って **すぐに移動** します。セットで使うことがほとんどなので `checkout -b` を覚えておけばOKです。

|---|---|

| セーブポイントを作る | `git commit -m "メッセージ"` |
| ブランチ一覧を見る | `git branch` |
| 新しいブランチを作って移動 | `git checkout -b ブランチ名` |
| 別のブランチに移動 | `git checkout ブランチ名` |
| コミット履歴を見る | `git log --oneline` |
